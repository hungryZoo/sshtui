# 작업 29: 한국어와 영어 표시 전환

먼저 저장소 루트의 `AGENTS.md`를 읽고 따른다. 이 작업에 한해 `AGENTS.md`의 "사용자에게 보이는 문자열은 영어로 작성" 규칙에 예외를 둔다: 문자열 표(`src/i18n.rs`) 안의 한국어 문자열은 허용한다. 주석과 문서 주석은 계속 영어로 쓴다.

## 목표

로캘이 한국어이면 TUI를 한국어로, 그 외에는 지금의 영어로 표시한다. 영어 표시는 지금과 바이트 단위로 같아야 한다(기존 테스트가 그대로 통과). 한국어 글자는 화면에서 2칸을 차지하므로 모든 열 맞춤과 자르기는 표시 폭 기준이어야 한다.

## 대상 파일

- `Cargo.toml`, `Cargo.lock`: 의존성 `sys-locale = "0.3.2"` 추가(이 작업이 명시적으로 허용. 레지스트리 캐시에 내려받아 두었으므로 `--offline`으로 빌드된다. 다른 의존성 변경 금지)
- `src/i18n.rs`(신규), `src/lib.rs`
- `src/main.rs`, `src/tui.rs`
- `src/app/` 전체, `src/ui/` 전체

`src/validate.rs`, `src/config/`, `src/ssh/`, `src/dialog/`, `src/known_hosts/`, `src/history.rs`, `src/update.rs`의 오류 타입과 메시지는 바꾸지 않는다.

## 1. 언어 결정 (`src/i18n.rs`)

```rust
/// Display language of the TUI.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum Lang { #[default] En, Ko }

/// Environment variable that forces the display language (`ko` or `en`).
pub const LANG_ENV: &str = "SSHTUI_LANG";

/// Classifies a locale name. None for empty, `C` and `POSIX`, which say nothing about language.
pub fn lang_of_locale(locale: &str) -> Option<Lang>;

/// Chooses the language from injected lookups.
pub fn detect(env: &dyn Fn(&str) -> Option<OsString>, system_locale: Option<&str>) -> Lang;

/// Returns the operating system's locale (thin wrapper over `sys_locale::get_locale`).
pub fn system_locale() -> Option<String>;
```

- `lang_of_locale`: 앞뒤 공백을 떼고, 비었거나 `C`, `POSIX`(대소문자 무시, `C.UTF-8` 포함)이면 `None`. 언어 부분(`_`, `-`, `.`, `@` 앞까지)이 대소문자 무시로 `ko`이면 `Some(Ko)`, 그 외는 `Some(En)`. 예: `ko`, `ko_KR.UTF-8`, `ko-KR`, `KO_kr` → Ko. `en_US.UTF-8`, `en_KR.UTF-8`, `ja_JP` → En.
- `detect` 우선순위: (1) `SSHTUI_LANG`이 `ko` 또는 `en`(대소문자 무시)이면 그 값. 다른 값은 무시 (2) `LC_ALL`, `LC_MESSAGES`, `LANG` 순서로 `lang_of_locale`이 `Some`인 첫 값 (3) `system_locale`의 `lang_of_locale` (4) `En`.
- macOS에서 터미널이 `LANG`을 설정하지 않아도 시스템 언어가 한국어이면 (3)으로 한국어가 된다.

## 2. 문자열 표

- 화면에 나오는 모든 문자열을 `src/i18n.rs`로 모은다. 구조는 자유이되 다음을 지킨다.
  - 고정 문자열은 언어별로 빠짐없이 정의되어야 컴파일된다(예: `&'static str` 필드를 가진 구조체의 `EN`, `KO` 상수 2개, 또는 `match (lang, 항목)`의 빠짐없는 `match`).
  - 값이 들어가는 문장은 `Lang`의 메서드나 함수로 만든다(예: `lang.removed_entries(count, name, backup) -> String`). 한국어는 어순이 다르므로 문장 조각을 이어 붙이지 않는다.
  - 영어 결과는 현재 화면 문자열과 완전히 같아야 한다.
- 대상: `src/ui/`의 모든 화면 문구(제목, 라벨, 안내, 키 안내의 설명, 플레이스홀더, 팝업 문구, 질문 줄과 선택지), `src/app/`이 만드는 모든 상태 메시지와 알림 문구, `ValidationError`의 화면 표시(영어는 지금의 표시 그대로, 한국어는 `i18n`에서 변환), `src/tui.rs`가 키 설치 전후에 터미널에 출력하는 문장.
- 번역하지 않는 것: 키 이름(`enter`, `esc`, `tab`, `ctrl+o`, `space`, `↑↓`, `←→`), `sshtui`, 명령 미리보기, 경로, 호스트 값, diff 내용, 하위 계층 오류 메시지(`WriteError`, `PlanError`, `SshError`, `KeySetupError`, 다이얼로그 사유와 안내, config 경고), `--help`와 `--version`과 `--check-update`와 `--update`의 출력.

## 3. 언어 전달

- `App`에 언어를 둔다. `App::new(backend)`는 `Lang::En`(기존 테스트 유지), `App::with_lang(backend, lang)` 추가, `pub fn lang(&self) -> Lang`.
- `src/main.rs`: `App::with_lang(backend, i18n::detect(&|name| std::env::var_os(name), i18n::system_locale().as_deref()))`. `--help`에 `SSHTUI_LANG` 설명 한 줄 추가(영어).

## 4. 표시 폭

- 번역 문자열이 들어가는 모든 채움과 정렬을 표시 폭(`unicode_width`) 기준으로 바꾼다. `format!("{:<N}")`, `{:>N}`, `.len()`, 글자 수 기준 계산은 문자 수로 채우므로 한글에서 열이 어긋난다. `src/ui/` 전체에서 이런 곳을 찾아 고친다(예: 폼의 라벨 열, `On enter` 단계의 동사 열, 목록 상세 열의 라벨, `read-only` 표시 폭).
- 라벨 열의 폭은 지금 값을 유지하되, 그 언어의 가장 긴 라벨이 들어가지 않으면 필요한 만큼만 넓힌다.
- 2칸 글자가 영역 끝에 반만 걸릴 때 깨진 글자가 보이지 않게 자른다.

## 5. 한국어 문구

문체: 짧은 명사형. 마침표와 가운뎃점(`·`)을 쓰지 않는다. 경어체 문장 금지(`~하세요`, `~합니다` 금지). 필요한 경우에만 `~함`, `~됨`이 아니라 명사로 끝낸다. 같은 개념은 같은 낱말로 쓴다.

## 필수 테스트

`src/i18n.rs`:

- `lang_of_locale`와 `detect`의 모든 우선순위 경우(`SSHTUI_LANG` 유효와 무효, `LC_ALL`이 `C`일 때 `LANG`으로 넘어감, 환경변수 없음과 시스템 로캘 `ko-KR`, 아무것도 없음)
- 영어 문자열 표의 대표 항목이 현재 문구와 같은지, 값이 들어가는 문장의 영어와 한국어 결과

`src/ui/tests.rs`(한국어, `App::with_lang(.., Lang::Ko)`):

- 목록(100x28): 머리줄 `호스트 N개`, 필터 바, 상세 열의 라벨 뒤 값이 모두 같은 열에서 시작(셀 좌표로 확인), `+ 새 접속` 줄, 키 안내 전체 문자열
- 목록 키 안내가 폭 96에서 잘리지 않고 마지막 쌍(`esc 종료`)까지 표시
- 새 접속 폼(100x28): 라벨 7개 뒤 입력칸과 체크 항목이 같은 열에서 시작, 안내 문구(`필수`, `선택, 입력하면 이 호스트를 저장`), `Enter 실행 내용` 단계의 동사 열 뒤 내용이 같은 열에서 시작, 키 안내
- 삭제 확인: 제목, 요약 줄, 질문 줄과 선택지, 백업 안내, 키 안내
- 호스트 키 삭제 확인, 키 목록 팝업, 히스토리 팝업, 불일치 알림, Update 팝업 각각의 제목과 키 안내
- 2칸 글자가 영역 끝에 걸리는 좁은 폭(예: 30)에서 패닉 없이 그려지고 줄이 화면 폭을 넘지 않음
- 검증 오류의 한국어 표시(빈 주소, 잘못된 포트, `-`로 시작하는 주소, 중복 닉네임)

`src/app/tests.rs`(한국어): 대표 상태 메시지 5종 이상(저장 완료, 삭제 완료, 호스트 키 삭제 완료, 항목 없음, 외부 변경 감지)의 한국어 문구.

## 기존 테스트 수정 허용 범위

없음. 영어 표시는 바뀌지 않으므로 기존 단언은 그대로 통과해야 한다. 충돌하면 고치지 말고 최종 보고에 적는다.

## 제약

- 새 의존성은 `sys-locale` 하나뿐. `unsafe` 금지.
- 실제 `~/.ssh`와 실제 홈 접근 금지. 테스트에서 `i18n::system_locale()`의 결과에 의존하지 않는다(값을 주입).

## 완료 조건

- `AGENTS.md`의 공통 완료 조건 3개 통과(`--offline`)
- `src/ui/`와 `src/app/`의 테스트가 아닌 코드에 화면용 영어 문장 리터럴이 남아 있지 않음(키 이름과 `sshtui` 제외). `grep`으로 확인하고 남긴 것이 있으면 이유와 함께 최종 보고에 나열
- 한국어 문자열 전체를 영어와 나란히 최종 보고에 표로 첨부
