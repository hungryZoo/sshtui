# 작업 10 재지시 1: 긴 문구가 잘리는 문제

먼저 저장소 루트의 `AGENTS.md`를 읽고 따른다. 작업 10(`tasks/10_tui.md`)의 결과물에 대한 수정이다. 100x30 터미널에서 실제 실행해 확인한 문제다.

## 대상 파일

- `src/ui/` 아래 파일

## 문제 1: 상태 메시지가 한 줄에서 잘림

위치: 상태 메시지를 그리는 부분(`src/ui/mod.rs`).

재현: 경로가 긴 ssh 디렉터리에서 외부 변경 감지가 일어나면 상태 줄에 경로만 보이고 뒤의 `was changed by another program; reloaded, try again`이 잘린다. 저장 후 `Saved web (backup: <긴 경로>` 도 뒤가 잘린다.

기대 동작:

- 상태 메시지는 화면 폭에 맞춰 줄바꿈하여 최대 3줄까지 표시한다. 필요한 줄 수만큼만 본문 영역을 줄인다(메시지가 없으면 0줄, 한 줄에 들어가면 1줄).
- 3줄을 넘으면 넘는 부분은 잘린다.
- 줄바꿈은 단어 경계 우선이되, 공백 없는 긴 경로는 문자 단위로 나눈다(`Wrap { trim: false }` 사용 시 긴 단어가 다음 줄로 넘어가는지 확인하고, 넘어가지 않으면 직접 폭 단위로 나눈다). 폭 계산은 `unicode-width` 기준이다.

## 문제 2: 확인 화면의 대상 파일 경로가 잘림

위치: 확인 화면(`src/ui/overlays.rs` 또는 해당 렌더 함수)의 파일 경로 줄.

기대 동작: 경로는 `paths.abbreviate_home`을 적용해 표시하고, 그래도 폭을 넘으면 줄바꿈하여 최대 2줄까지 표시한다.

## 문제 3: 목록 상세 패널의 항목 순서

위치: `src/ui/list.rs`의 상세 패널.

현재 `Source`가 `Port`와 `Key file` 사이에 있다. 기대 순서는 `Alias`, `User`, `Address`, `Port`, `Key file`(여러 줄), `Source`, (읽기 전용이면) `Read-only file`이다. `Source` 경로가 폭을 넘으면 줄바꿈한다(현재 동작 유지).

## 추가할 테스트 (`TestBackend`)

1. 폭 40에서 80자짜리 상태 메시지(공백 없는 긴 경로 뒤에 `was changed by another program` 문구)가 여러 줄로 표시되어 버퍼 전체 텍스트(줄을 이어 붙인 것)에 문구 끝부분이 포함됨
2. 상태 메시지가 없을 때와 짧을 때 본문 영역 높이가 각각 줄어들지 않음과 1줄만 줄어듦(목록 항목이 보이는 줄 수로 확인)
3. 상태 메시지가 3줄을 넘어도 패닉 없이 3줄까지만 차지
4. 확인 화면에서 홈 하위 경로가 `~/...` 형태로 표시됨
5. 폭 30에서 확인 화면의 긴 경로가 2줄에 걸쳐 표시됨
6. 상세 패널에서 `Key file` 줄이 `Source` 줄보다 위에 있음
7. 작은 크기(1x1, 5x2, 20x5)에서 긴 상태 메시지가 있어도 패닉 없음
