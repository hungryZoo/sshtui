먼저 저장소 루트의 `AGENTS.md`를 읽고 따른다. `tasks/11_readme.md`의 "작성 원칙"과 "구조 (위키형)"을 그대로 적용한다(한국어, 명사형 개조식, 비유 금지, 원 숫자 기호 금지, 범위는 `-`, 목차 앵커 일치). 가운뎃점은 화면 문구를 인용하는 코드 표기 안에서만 허용한다.

## 목표

작업 31의 변경을 `README.md`에 반영한다. 코드는 수정하지 않는다. `src/app/list.rs`, `src/app/mod.rs`, `src/ui/mod.rs`, `src/ui/list.rs`, `src/ui/theme.rs`와 대조해 확인한다.

## 변경 내용

1. `공통 화면 구성`: 맨 아래 키 안내의 첫 쌍 설명을 고친다. 키 부분만 배지라는 서술을 지우고, 포커스된 쌍이 키와 설명과 좌우 1칸을 포함한 강조색 버튼으로 표시된다는 점, 목록 이외의 화면과 팝업에서는 항상 첫 쌍이 버튼이라는 점, 비활성 첫 쌍의 표시를 적는다.
2. `호스트 목록`:
   - new 줄 서술에서 오른쪽의 `n` 표시를 지운다(README 전체에서 `+ New connection`과 `n`을 함께 언급한 곳을 찾아 고친다).
   - 키 표에 `←`, `→` 행 추가: 키 안내의 항목 사이 포커스 이동(접속 또는 새 접속, 편집, 삭제, known_host 삭제, 필터, 다시 읽기, 종료 또는 필터 해제의 7개, 양 끝에서 멈춤), `Enter`는 포커스된 항목 실행.
   - 포커스가 첫 항목으로 돌아가는 조건(소스에서 확인): `←`, `→` 이외의 키 입력, 클릭 대상이 있는 곳의 클릭, 휠, 붙여넣기, 다른 화면에서 돌아올 때, 재로드, 실행 직후. 필터 입력 중에는 이동 없음.
   - 넘침 규칙에 "포커스된 쌍은 생략하지 않음" 추가.
3. `마우스` 절과 호버 설명 표: 키 안내에 올렸을 때의 표현을 버튼 모양(강조색 배경, 어두운 글자)으로 고치고, 클릭 영역이 쌍의 좌우 1칸까지라는 점을 적는다. 16색 모드의 표현도 소스와 대조해 고친다.
4. `검증 상태` 표: 단위 테스트 수를 `cargo test --offline`의 실제 결과로 갱신하고 수동 행 1개 추가.
   - 항목: `키 안내 버튼: tmux 창(100x28, 한국어)에서 트루컬러 배경 코드로 첫 쌍 전체가 강조색 배경인지, →와 ←로 버튼이 편집, known_host 삭제, 종료까지 이동하고 양 끝에서 멈추는지, 편집에 포커스를 두고 Enter로 편집 폼이 열리는지, 목록으로 돌아오거나 ↑를 누르면 포커스가 첫 쌍으로 돌아가는지, new 줄에 n이 없는지`
   - 상태: `확인 (macOS, tmux)`
   - 미검증 행의 "실제 마우스 장치" 항목에 "키 안내 호버의 버튼 표현 체감"을 추가
5. `수동 확인 절차`: 목록 확인 단계에 `→`, `←`, `Enter` 확인 단계 추가.
