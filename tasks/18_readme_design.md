# 작업 18: README에 새 화면 디자인 반영

먼저 저장소 루트의 `AGENTS.md`를 읽고 따른다. `tasks/11_readme.md`의 "작성 원칙"과 "구조 (위키형)"을 그대로 적용한다(한국어, 명사형 개조식, 비유 금지, 원 숫자 기호 금지, 범위는 `-`, 목차 앵커 일치). 가운뎃점은 화면 문구를 그대로 인용하는 코드 표기(`optional · fill in to save this host`) 안에서만 허용한다.

## 목표

작업 17에서 화면이 `docs/design/`의 목업대로 바뀌었다. `README.md`의 화면 설명, 키 표기, 문구 인용을 현재 소스에 맞춘다. 코드는 수정하지 않는다. 모든 내용은 `src/ui/`, `src/app/`, `src/tui.rs`, `src/main.rs`와 대조해 확인한다.

## 대상 파일

- `README.md`

## 변경 내용

1. 없어진 요소의 서술을 지운다: 둥근 테두리 패널, `[ Keys F2 ]`, `[ Browse F3 ]`, `[ Connect ]`, `[ Save ]`, `[ Cancel ]`, `[ Confirm y ]`, `[ Cancel n ]`, `[ OK ]`, `[ Back ]`, `[ Close ]`, `[ Update and exit ]`, `[ Connect anyway ]` 버튼, `Command` 패널, 목록의 `ro` 표시, 제목 줄의 `v<버전> available (u: update)` 문구. README 전체에서 이 문자열들을 `grep`으로 찾아 현재 화면 기준으로 고친다.
2. 화면 설명을 현재 화면으로 다시 쓴다(소스에서 확인).
   - 공통: 머리줄(`sshtui`, 화면 제목, 오른쪽 보조 정보), 가로 구분선, 맨 아래 키 안내(첫 쌍은 배지), 상태 메시지 위치
   - 호스트 목록: 필터 바(`/ filter hosts`), 줄 구성(선택 표시 `›`, 이름, 블록에 직접 적힌 값으로 만든 `user@host` 요약, 읽기 전용 줄의 `read-only`), 상세 열(별칭, `user@address`, `User`/`Address`/`Port`/`Key file`/`Source`, `enter runs`와 실행될 명령), 폭 64 미만에서 상세 열 생략, 업데이트 알림 `update available u`
   - 접속 폼: 필드 줄(선택 표시, 라벨, 입력칸, 안내 문구), `On enter` 영역의 4가지 경우(닉네임 있음, 없음, 편집, 검증 오류), 검증 오류 표시 위치, 포커스에 따라 바뀌는 키 안내(Key file이면 `ctrl+l pick key`와 `ctrl+o browse`, 다른 필드면 `ctrl+u clear field`), 새 접속 폼의 빈 Port 칸에 보조 표시되는 `22`
   - 변경 확인: 요약 줄(`N lines will change`, 삭제와 추가 수), 줄 번호 두 열과 기호, 백업 안내 줄(`The current file is kept as ...`), 키 안내
   - 팝업(키 목록, 불일치 알림, Update): 뒤 화면이 흐려지고 직각 테두리 상자, 키 목록 줄 구성(경로와 `.pub`의 종류와 코멘트), 각 팝업의 키 안내
3. 키 표: 화면의 키 안내 표기(소문자 `enter`, `esc`, `tab`, `ctrl+l`, `ctrl+o`, `ctrl+u`, `↑↓`)와 실제로 동작하는 키를 구분해 쓴다. `F2`와 `F3`은 화면에 표시되지 않지만 계속 동작한다는 점을 접속 폼 키 표에 남긴다. `ctrl+l`과 `ctrl+o`는 어느 필드에서나 동작하고 안내만 Key file 포커스에서 보인다는 점도 적는다.
4. `마우스` 절: 버튼 클릭 행을 지우고, 필터 바 클릭(필터 입력 시작) 행을 추가한다. 키 안내 클릭에서 `ctrl+u`와 `↑↓`는 클릭 대상이 아니라는 점을 적는다.
5. 새 하위 절 `색` 을 `3. 사용법`의 `환경변수` 앞에 추가(목차 포함):
   - 환경변수 `COLORTERM`이 `truecolor` 또는 `24bit`이면 목업의 24비트 팔레트로 그리고 화면 전체 배경을 칠함
   - 그 외에는 터미널 기본 16색을 쓰고 배경을 칠하지 않으며 입력칸은 밑줄로 표시
   - 팔레트 표(이름, 값, 용도): `src/ui/theme.rs`의 값 그대로
6. `검증 상태` 표 갱신:
   - 단위 테스트 수 369개
   - 화면 관련 수동 행을 다음으로 교체: `디자인 목업(docs/design) 6장과의 대조: 목업과 같은 표본 호스트 12개, 100x28 창에서 목록, 필터, 새 접속, 편집 오류, 키 목록, 변경 확인 화면의 배치와 문구, 트루컬러 색 코드(배경, 강조, 삭제 줄 배경 등), COLORTERM 미설정 시 16색 전환` / `확인 (macOS, tmux)`
   - 마우스 수동 행의 내용에서 "버튼"을 빼고 "필터 바"를 넣는다
   - 미검증 행 추가: `실제 터미널 앱에서의 색 표현과 글꼴 렌더링(목업의 JetBrains Mono, 줄 간격 24px은 터미널 설정에 따름)` / `미검증`
7. `개발` 절: 모듈 구성 표의 `src/ui/` 설명을 현재 파일 구성에 맞추고, 디자인 원본이 `docs/design/`(Claude Design 캔버스에서 가져온 `.dc.html` 목업 6장과 `canvas.json`)에 있다는 한 줄을 추가한다.
8. `수동 확인 절차`의 단계 가운데 버튼이나 이전 문구를 언급하는 곳을 현재 화면에 맞게 고친다.
