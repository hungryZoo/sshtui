# 작업 14: 화면 디자인 개선

먼저 저장소 루트의 `AGENTS.md`를 읽고 따른다. `src/ui/`(현재 렌더러와 테스트)와 `src/app/`의 접근자를 읽는다.

## 목표

현재 화면은 테두리와 정렬, 강조가 거의 없는 텍스트 나열이다. 같은 정보를 패널, 정렬된 표, 일관된 색으로 다시 배치한다. 상태 전이와 키 동작은 바꾸지 않는다. 다음 작업(15)에서 버튼과 줄을 마우스로 누를 수 있게 하므로, 버튼과 목록 줄의 위치 계산은 재사용하기 쉬운 함수로 둔다.

## 대상 파일

- `src/ui/` 아래 파일(신규 `src/ui/theme.rs` 포함)
- `src/app/`: 렌더러에 필요한 읽기 전용 접근자 추가만 허용. 상태 전이와 `src/app/tests.rs`는 수정하지 않는다.

`src/ui/tests.rs`의 기존 테스트는 배치가 바뀌어 기대 문자열이 달라지는 경우에 한해 새 배치에 맞게 고칠 수 있다. 이때 각 테스트가 확인하던 의도(어떤 정보가 화면에 보이는지, 순서, 줄 수, 색, 커서 위치, 작은 화면에서 패닉 없음)는 유지한다. 테스트를 지우거나 단언 수를 줄이지 않는다. 고친 테스트는 최종 보고에 목록으로 적는다.

## 테마 (`src/ui/theme.rs`)

색과 스타일은 이 파일의 함수와 상수로만 정의하고 다른 파일에서 색을 직접 쓰지 않는다. 16색 기본 팔레트만 사용한다(RGB 금지).

| 용도 | 스타일 |
|---|---|
| 강조(ACCENT) | `Color::Cyan` |
| 흐림(MUTED) | `Color::DarkGray` |
| 오류 / 경고 / 성공 | `Red` / `Yellow` / `Green` |
| 선택된 줄 | 배경 Cyan, 글자 Black, 굵게 |
| 테두리 | `BorderType::Rounded`. 활성 패널은 ACCENT, 비활성은 MUTED |
| 주 버튼 | 배경 Cyan, 글자 Black, 굵게. 형태 `[ Label ]` |
| 보조 버튼 | 글자 기본색, 형태 `[ Label ]` |
| 비활성 버튼 | MUTED |
| 키 안내 | 키는 ACCENT 굵게, 설명은 MUTED |

굵게나 배경색이 옆 텍스트로 번지지 않게 span 단위로 스타일을 준다.

## 공통 틀

- 맨 위 1줄(머리줄): 왼쪽에 배지 ` sshtui `(배경 Cyan, 글자 Black, 굵게), 한 칸 띄우고 화면 제목(목록은 `4 hosts` 또는 `1 of 4 hosts`, 폼은 `New connection` 또는 `Edit <alias>`, 확인은 `Save <alias>` 또는 `Delete <alias>`). 오른쪽 끝에 업데이트 알림(목록 화면, 노랑 굵게, 폭이 부족하면 생략). 기존 제목의 가운뎃점 문자는 쓰지 않는다.
- 본문.
- 상태 메시지(0-3줄, 기존 줄바꿈 규칙 유지): Info는 Green, Warning은 Yellow, Error는 Red.
- 맨 아래 1줄(키 안내): 기존 문구를 그대로 쓰되 `<키> <설명>` 쌍마다 키는 ACCENT 굵게, 설명은 MUTED. 쌍 사이는 공백 2칸. 문구 예: `Enter connect  n new  e edit  d delete  / filter  r reload  u update  q quit`.

키 안내는 `(키 문자열, 설명)` 쌍의 목록으로 만들고 그 목록에서 줄을 그린다(다음 작업에서 쌍마다 클릭 영역을 만든다). 버튼도 `(라벨, 종류)` 목록에서 그리고, 버튼 하나가 차지한 `Rect`를 돌려주는 함수로 그린다.

## 목록 화면

```
 sshtui  4 hosts                                   v9.9.9 available (u: update)
╭ Hosts ───────────────────╮╭ web ─────────────────────────────────────────────╮
│ web                      ││ User       alice                                 │
│ db                    ro ││ Address    127.0.0.1                             │
│ cache                    ││ Port       2222                                  │
│ inc                      ││ Key file   ~/.ssh/id_ed25519                     │
│                          ││                                                  │
│                          ││ Source     ~/.ssh/config:2                       │
╰──────────────────────────╯╰──────────────────────────────────────────────────╯
 Enter connect  n new  e edit  d delete  / filter  r reload  q quit
```

- 왼쪽 패널 `Hosts`(활성 테두리). 폭은 가장 긴 이름 + 여백 기준으로 24-40칸, 전체 폭의 절반을 넘지 않는다.
  - 줄: 앞 여백 1칸 + 이름. 읽기 전용이면 오른쪽 끝에 `ro`(Yellow). 선택된 줄은 패널 안쪽 폭 전체에 선택 스타일.
  - 선택 항목이 보이도록 스크롤(기존 동작 유지).
  - 필터 입력 중이거나 필터가 있으면 패널 안 첫 줄에 `/`(ACCENT)와 필터 문자열을 표시하고 목록은 그 아래에 둔다. 입력 중이면 커서를 그 위치에 둔다.
  - 결과가 없으면 패널 가운데에 MUTED로 `No matching hosts`.
- 오른쪽 패널(비활성 테두리). 제목은 선택된 별칭.
  - 라벨 열(폭 10, MUTED)과 값 열의 2열 정렬: `User`, `Address`, `Port`, `Key file`(여러 개면 라벨은 첫 줄만, 값은 줄마다), 빈 줄, `Source`(`<경로>:<줄 번호>`, 홈 하위는 `~` 축약, 길면 값 열 안에서 줄바꿈)
  - 읽기 전용이면 마지막에 Yellow로 `Read-only file`
  - 적용값 조회 실패 시 Red로 `Effective settings: <오류>`(줄바꿈)
  - 선택 항목이 없으면 패널을 비워 둔다.
- 전체 폭이 50칸 미만이면 오른쪽 패널을 그리지 않고 왼쪽 패널이 전체 폭을 쓴다.

## 폼 화면

```
 sshtui  New connection
╭ New connection ───────────────────────────────────────────────────────────────╮
│ Nickname   ______________________________________________________  optional   │
│ User       ______________________________________________________  optional   │
│ Address    127.0.0.1_____________________________________________  required   │
│ Port       ______________________________________________________  optional   │
│ Key file   ______________________________________________________  optional   │
│                                                                               │
│ [ Keys F2 ]  [ Browse F3 ]                                                    │
│                                                                               │
│ ╭ Command ──────────────────────────────────────────────────────────────────╮ │
│ │ ssh 127.0.0.1                                                             │ │
│ ╰───────────────────────────────────────────────────────────────────────────╯ │
│                                                                               │
│ [ Connect ]  [ Cancel ]                                                       │
╰───────────────────────────────────────────────────────────────────────────────╯
 Tab/Shift+Tab move  Enter connect  Esc back
```

(위 그림의 `_`는 밑줄 스타일이 적용된 입력 영역을 나타낸다. 실제로는 공백에 `Modifier::UNDERLINED`를 준다.)

- 바깥 패널(활성 테두리), 제목은 `New connection` 또는 `Edit <alias>`.
- 공유 알림(`shared_notice`)이 있으면 패널 안 맨 위에 Yellow로 줄바꿈해 표시하고 한 줄 띈다.
- 필드 줄: 라벨 열(폭 10) + 입력 영역 + 안내 열.
  - 라벨: `Nickname`, `User`, `Address`, `Port`, `Key file`. 포커스 필드의 라벨은 ACCENT 굵게, 나머지는 기본색.
  - 입력 영역: 값과 남는 칸 전체에 밑줄. 포커스 필드는 밑줄을 ACCENT로. 값이 길면 커서가 보이도록 가로 스크롤(기존 `input_window` 동작 유지). 커서는 `frame.set_cursor_position`으로 표시.
  - 값이 비어 있고 placeholder가 있으면 입력 영역에 MUTED로 `inherited: <값>`.
  - 읽기 전용 필드: 입력 영역 대신 MUTED로 원문 줄(여러 줄이면 아래로 이어서), 안내 열에 `read-only`(Yellow).
  - 안내 열(새 접속 폼만): `optional` 또는 `required`(MUTED). 편집 폼의 Nickname은 `required`.
  - 검증 오류: 그 필드의 값이 비어 있지 않을 때만 필드 줄 바로 아래에 입력 영역 열에 맞춰 Red로 표시한다. 값이 빈 필수 필드의 오류는 필드 아래에 표시하지 않는다(제출 시 상태 메시지와 Command 영역이 알려 준다).
- 키 파일 버튼 줄: `[ Keys F2 ]`(보조), `[ Browse F3 ]`(보조). 찾아보기 비활성 사유가 있으면 `[ Browse F3 ]`를 비활성 스타일로 그리고 그 오른쪽에 MUTED로 사유를 표시한다. `hidden_files_hint`가 있으면 다음 줄에 MUTED로 표시한다.
- `Command` 안쪽 패널(비활성 테두리, 제목 `Command`): 미리보기 명령(기본색, 최대 3줄 줄바꿈). 오류면 Red로 `(<오류>)`.
- 아래 버튼 줄: 새 접속은 `[ Connect ]`(주), 편집은 `[ Save ]`(주), 이어서 `[ Cancel ]`(보조).
- 높이가 부족하면 아래 요소부터 생략한다(버튼 줄, Command 패널, 키 파일 버튼 줄 순). 필드 5줄과 커서는 가능한 한 끝까지 보인다.

## 변경 확인 화면

- 패널(활성 테두리), 제목 `Save <alias>` 또는 `Delete <alias>`.
- 첫 줄에 대상 파일 경로(MUTED, `~` 축약, 최대 2줄), 한 줄 띄고 diff.
- diff 줄: 줄 번호 두 열(MUTED), 기호와 내용(`-`는 Red, `+`는 Green, 문맥은 기본색). hunk 사이에는 MUTED 구분 줄.
- 패널 안 맨 아래에 버튼 줄: `[ Confirm y ]`(주), `[ Cancel n ]`(보조). diff 영역은 버튼 줄 위까지.
- 스크롤 위치 반영(기존 동작 유지).

## 팝업 (키 목록, 알림, Update)

- 팝업 아래를 `Clear`로 지우고 ACCENT 둥근 테두리와 굵은 제목으로 그린다. 뒤 화면은 그대로 보인다.
- 키 목록: `KeyInfo::label()` 줄, 선택 줄은 선택 스타일.
- 알림: 본문 줄(Yellow) 아래에 버튼 줄. 접속으로 이어지면 `[ Connect anyway ]`(주)와 `[ Back ]`(보조), 아니면 `[ OK ]`(주).
- Update: 라벨 열 정렬(`Current`, `Latest`, `Installed via`), `Command` 다음 줄부터 단계(또는 `Download`와 URL), 아래에 버튼 줄. 실행 가능하면 `[ Update and exit ]`(주)와 `[ Cancel ]`(보조), 아니면 `[ Close ]`(주).
- 맨 아래 키 안내 문구는 기존과 같다.

## 작은 화면

어떤 크기(1x1 포함)에서도 패닉이 없어야 한다. 테두리를 그릴 공간이 없으면 테두리 없이 그릴 수 있는 것만 그린다. 영역 계산은 `saturating_sub`를 쓴다.

## 테스트

기존 테스트를 새 배치에 맞춰 유지하고 아래를 추가한다(`TestBackend`).

1. 목록: 두 패널의 제목(`Hosts`, 선택된 별칭)과 둥근 테두리 문자, 상세의 라벨과 값이 같은 줄에 있고 값의 시작 열이 모든 줄에서 같음
2. 목록: 선택된 줄의 셀 스타일이 선택 스타일(배경 Cyan)이고 선택되지 않은 줄은 아님
3. 목록: 폭 49에서는 상세 패널이 없고 폭 50에서는 있음
4. 목록: 읽기 전용 줄의 `ro`가 Yellow이고 줄 오른쪽 끝에 있음
5. 머리줄: 배지 셀의 배경이 Cyan, 제목 문구, 가운뎃점 문자 없음
6. 키 안내: 키 셀은 Cyan 굵게, 설명 셀은 DarkGray
7. 폼: 포커스 필드의 입력 영역 셀에 밑줄 수정자가 있고 색이 Cyan, 다른 필드는 밑줄만
8. 폼: 값이 빈 Address에는 필드 아래 오류 줄이 없고, `-x`를 입력하면 바로 아래 줄에 Red 오류 문구
9. 폼: `[ Keys F2 ]`, `[ Browse F3 ]`, `[ Connect ]`, `[ Cancel ]` 표시. 편집 폼은 `[ Save ]`. 찾아보기 비활성 시 버튼 셀이 DarkGray이고 사유 표시
10. 폼: `Command` 패널에 미리보기, 오류일 때 Red
11. 확인: 버튼 2개와 diff의 색(Red, Green), 경로 MUTED
12. 팝업 3종: 버튼 문구, 팝업 영역 안에 뒤 화면 글자가 남지 않음(`Clear`)
13. 상태 메시지 색: Info Green, Warning Yellow, Error Red
14. 모든 화면 종류가 1x1, 5x2, 20x5, 40x10, 80x24, 200x60에서 패닉 없이 그려짐
