# 작업 31: 키 안내를 버튼으로 표시하고 목록에서 좌우로 이동

먼저 저장소 루트의 `AGENTS.md`를 읽고 따른다. 화면 문자열은 `src/i18n.rs`를 통해서만 쓴다.

## 목표

1. 목록 맨 아래 new 줄(`+ New connection`)의 오른쪽에 표시하던 `n`을 없앤다.
2. 맨 아래 키 안내의 첫 쌍은 지금 키 부분(` enter `)만 강조색 배지다. 이것을 키와 설명 전체(`enter connect`)가 강조색인 버튼으로 바꾼다(모든 화면 공통).
3. 호스트 목록에서는 `←`, `→`로 키 안내의 항목 사이를 이동할 수 있고, 포커스된 항목이 버튼으로 표시되며, `Enter`가 포커스된 항목을 실행한다.
4. 마우스를 올린 항목도 버튼 모양으로 표시한다.

## 대상 파일

- `src/app/mod.rs`, `src/app/list.rs`, `src/app/tests.rs`
- `src/ui/mod.rs`, `src/ui/list.rs`, `src/ui/theme.rs`, `src/ui/hover.rs`, `src/ui/tests.rs`
- `src/i18n.rs`(쓰지 않게 된 문자열 정리에 필요할 때만)

## 1. new 줄

- new 줄에는 `+ New connection`(한국어 `+ 새 접속`)만 그린다. 요약 열의 `n`은 제거. 선택 표시, 클릭, 호버는 그대로.

## 2. 버튼 모양 (`render_help`)

글자 배치는 바꾸지 않는다. 쌍의 폭, 쌍 사이 간격(3칸), 화면의 문자열은 지금과 같아야 하고 스타일만 바뀐다.

- 버튼 영역: 쌍의 글자 범위에 좌우 1칸씩 더한 범위. 첫 쌍은 이미 앞에 공백 1칸이 있으므로(` enter  connect`) 그 15칸과 뒤 간격의 첫 1칸까지 16칸. 다른 쌍은 앞 간격의 마지막 1칸, 쌍, 뒤 간격의 첫 1칸. 화면 끝이라 뒤 칸이 없으면 있는 범위까지만.
- 버튼 스타일: 영역 전체가 강조색 배경(`theme.badge(true)`와 같은 배경), 키는 굵은 어두운 글자, 설명은 굵지 않은 어두운 글자(배경색과 대비되는 `bg` 색). 16색 모드는 지금의 활성 배지와 같은 방식(강조 배경)으로 영역 전체를 칠한다.
- 버튼으로 그리는 쌍: "포커스된 쌍" 하나. 목록 화면(필터 입력 중이 아닐 때)에서는 3절의 포커스, 그 밖의 모든 화면과 팝업에서는 항상 첫 쌍.
- 포커스가 아닌 쌍은 지금의 일반 쌍 모양(굵은 키, 흐린 설명). 첫 쌍이 포커스를 잃은 경우도 일반 쌍 모양으로 그리되 글자 위치는 그대로 둔다.
- 첫 쌍이 비활성(`enabled == false`)이고 포커스일 때: 지금의 비활성 배지 색(`theme.badge(false)`)을 버튼 영역 전체에 적용하고 호버 반응 없음.
- 호버: 클릭 대상이 있는 쌍에 마우스를 올리면 기존 150ms 진행값 `t`에 따라 버튼 모양으로 변한다. 포커스가 아닌 쌍은 일반 모양에서 버튼 모양(강조색 배경, 어두운 글자)으로 색을 섞어 전환. 포커스된 버튼은 지금처럼 `HOVER_ACCENT` 쪽으로 밝아짐. 16색 모드는 `t >= 0.5`에서 버튼 모양.
- 클릭 영역은 버튼 영역 전체로 넓힌다(좌우 1칸 포함). 이웃 쌍의 버튼 영역은 간격이 3칸이므로 겹치지 않는다. 가운데 1칸은 지금처럼 클릭 대상 없음.

## 3. 목록의 좌우 이동

상태(`src/app/`):

```rust
/// An action on the host list's key bar, in display order.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ListAction { Open, Edit, Delete, Forget, Filter, Reload, Leave }

impl ListAction {
    /// All actions in display order.
    pub const ALL: [Self; 7];
}

/// Returns the action that Enter runs on the host list.
pub fn list_action(&self) -> ListAction;
```

- `Open`은 지금의 `Enter`(호스트 줄이면 접속, new 줄이면 새 접속 폼). `Leave`는 지금의 `Esc`(필터가 적용되어 있으면 필터 해제, 아니면 종료). 나머지는 각각 `e`, `d`, `x`, `/`, `r`과 같은 동작.
- 시작 값은 `Open`.
- 목록에서 필터 입력 중이 아닐 때 `→`는 다음 항목, `←`는 이전 항목으로 포커스 이동. 양 끝에서 멈춘다(순환하지 않음).
- `Enter`는 포커스된 항목을 실행한다. 실행 직후 포커스는 `Open`으로 돌아간다.
- 포커스가 `Open`으로 돌아가는 경우: `←`, `→` 이외의 모든 키 입력(위아래 이동, 단축키, `Esc` 포함), 클릭, 휠, 붙여넣기, 다른 화면에 갔다가 목록으로 돌아올 때, 재로드. 즉 `Open`이 아닌 포커스는 `←`/`→`와 바로 이어지는 `Enter` 사이에서만 유지된다.
- 필터 입력 중에는 `←`, `→`를 지금처럼 무시하고 포커스는 `Open`.
- 단축키(`e`, `d`, `x`, `/`, `r`, `n`, `i`, `u`, `Esc`, `q`)의 동작은 그대로.

화면(`src/ui/list.rs`, `src/ui/mod.rs`):

- 목록의 키 안내 7쌍이 `ListAction::ALL`과 같은 순서로 대응한다. `app.list_action()`에 해당하는 쌍이 버튼.
- 넘침 규칙 보완: 폭이 부족해 쌍을 뺄 때 포커스된 쌍은 빼지 않는다. 뺄 차례가 포커스된 쌍이면 건너뛰고 그 왼쪽 쌍을 뺀다. 첫 쌍과 마지막 쌍을 유지하는 기존 규칙은 그대로.
- 키 안내의 키 이름과 설명 문구는 바꾸지 않는다(첫 쌍은 `enter connect` 또는 `enter new`, 포커스를 옮겨도 각 쌍의 단축키 표기는 그대로).

## 필수 테스트

`src/app/tests.rs`:

- `→`를 6번 누르면 `Leave`, 더 눌러도 `Leave`. `←`로 되돌아가 `Open`에서 멈춤
- 각 항목에 포커스를 두고 `Enter`: `Edit`은 편집 폼, `Delete`는 삭제 확인(선택 Cancel), `Forget`은 호스트 키 삭제 흐름(가짜 백엔드의 `plan_forget` 호출), `Filter`는 필터 입력 시작, `Reload`는 재로드와 `Reloaded` 메시지, `Leave`는 종료. 필터 적용 상태의 `Leave`는 필터 해제이고 종료하지 않음
- `Enter` 실행 뒤, `↓` 입력 뒤, 클릭 뒤, 휠 뒤, 폼에서 `Esc`로 돌아온 뒤 `list_action() == Open`
- 포커스가 `Delete`일 때 `↓` 후 `Enter`는 접속(삭제 확인이 열리지 않음)
- new 줄 선택 상태에서 `→` 후 `Enter`(`Edit`)는 아무 일도 하지 않음, `Open`의 `Enter`는 새 접속 폼
- 필터 입력 중 `→`는 포커스를 바꾸지 않음
- 호스트가 선택된 상태에서 포커스 이동이 선택 줄을 바꾸지 않음

`src/ui/tests.rs`:

- 목록(100x28)의 키 안내 문자열이 이전과 동일
- 시작 상태: 첫 쌍의 버튼 영역 16칸이 모두 강조색 배경, 설명 글자의 전경색이 어두운 색, 그다음 칸부터는 기본 배경
- `→` 한 번: 첫 쌍은 기본 배경(키는 굵게, 설명은 흐린 색), `e edit` 쌍과 좌우 1칸이 강조색 배경
- `→` 여섯 번: 마지막 쌍(`esc quit`)이 버튼
- 좁은 폭(예: 60)에서 포커스가 `Reload`일 때 `r reload`가 표시되고 다른 쌍이 빠짐
- 클릭 영역: 버튼 영역의 좌우 1칸에서도 해당 `ClickTarget::Key`, 쌍 사이 가운데 칸은 대상 없음
- 호버: 포커스가 아닌 쌍에 완전히 올렸을 때(`t == 1`) 버튼 스타일, 중간값에서 섞인 색, 16색 모드의 `t >= 0.5`
- new 줄에 `n`이 없음(영어와 한국어)
- 폼, 삭제 확인, 키 목록 팝업, 히스토리 팝업의 첫 쌍이 전체 버튼 스타일
- 비활성 첫 쌍(검증 오류가 있는 폼)의 스타일
- 한국어 목록에서 `→` 두 번 뒤 `d 삭제` 쌍의 버튼 영역(2칸 글자 포함)이 정확한 칸 범위

## 기존 테스트 수정 허용 범위

- 키 안내 칸의 스타일(배경, 전경, 굵기) 기대값과 호버 색 기대값
- 키 안내 클릭 영역의 경계 기대값(좌우 1칸 확장)
- new 줄의 `n`을 확인하던 기대값

화면 문자열을 비교하는 기존 단언은 new 줄을 빼고 그대로 통과해야 한다. 고친 테스트 이름과 이유를 최종 보고에 전부 나열한다.
