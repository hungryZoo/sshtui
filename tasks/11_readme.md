## 작성 원칙

- 한국어로 작성한다. 화면에 나오는 문구, 키, 명령, 식별자는 원문(영어) 그대로 쓴다.
- README의 모든 주장(키, 옵션, 환경변수, 파일 이름, 동작)은 소스 코드와 대조해 확인한 것만 쓴다. 이 지시문의 내용과 소스가 다르면 소스를 따르고 최종 보고에 차이를 적는다. 확인할 위치: `src/app/mod.rs`(키 처리), `src/ui/`(화면 문구), `src/config/`(읽기, 편집, 쓰기 규칙), `src/dialog/`(다이얼로그), `src/ssh/`(인자와 실행), `src/validate.rs`, `src/paths.rs`, `src/main.rs`.
- 문체: 간결한 명사형 개조식 위주. 비유 금지. 제목은 명사형. 범위는 `-`로 표기(예: 1-65535). 나열에 가운뎃점(`·`) 금지, 쉼표나 "와/과" 사용. 번호는 (1), (2) 형태 또는 마크다운 번호 목록. 원 숫자 기호(①) 금지.
- 버전 숫자를 명령에 넣지 않는다.
- 릴리스, 라이선스, 스크린샷, 데모 영상은 아직 없으므로 넣지 않는다. 없는 것을 있는 것처럼 쓰지 않는다.

- 최상위 절 제목에 번호: `## 1. 개요`, `## 2. 설치` 등
- 최상위 절마다 끝에 `<p align="right"><a href="#table-of-contents">↑ back to top</a></p>`
- GitHub 앵커 규칙: 소문자, 공백은 `-`, 문장부호와 백틱 제거, `_` 유지, 한글 유지. 예: `## 2. 설치`는 `#2-설치`. 작성 후 목차의 모든 링크가 실제 제목과 일치하는지 확인한다.

절 구성과 담을 내용:

### 1. 개요

- 기능 목록: 저장된 호스트 목록에서 접속, 폼으로 새 접속, 닉네임을 붙이면 `~/.ssh/config`에 저장, 편집과 삭제, 키 파일 선택 3가지 방법
- 동작 방식 표: 저장소는 `~/.ssh/config`(별도 DB 없음), 접속은 시스템 `ssh` 실행(SSH 프로토콜 미구현), 적용값 확인은 `ssh -G`, 저장한 호스트는 터미널에서 `ssh <닉네임>`으로도 사용 가능
- 범위 외: 포트 포워딩과 ProxyJump 등 고급 옵션 편집 UI, 그룹과 태그, 접속 기록, scp와 sftp, 비밀번호 저장

### 2. 설치

- 요구 사항: Rust stable 툴체인, PATH의 OpenSSH 클라이언트(`ssh`)
- 소스에서 설치: `cargo install --path .` 또는 `cargo build --release` 후 `target/release/sshtui`
- crates.io에는 배포하지 않음(`publish = false`)

### 3. 사용법

- 실행: `sshtui`. 옵션 `-h`/`--help`, `-V`/`--version`
- 화면별 하위 절과 키 표(소스에서 확인해 작성):
  - 호스트 목록: 시작 화면, 호스트가 없으면 바로 접속 폼. 상세 패널 항목. 읽기 전용 표시 `[ro]`
  - 접속 폼: 필드 5개와 필수 여부, 새 접속에서 Enter의 두 가지 동작(닉네임 있음과 없음), 편집에서 Enter, 비어 있는 필드는 옵션 생략, 실시간 미리보기, 키 파일 지정 3가지(키 목록, 찾아보기, 직접 입력과 `~` 확장)
  - 변경 확인(diff), 키 목록, 알림(저장값과 적용값 불일치)
- 접속 실행: TUI 종료와 터미널 복원 후 ssh 실행. Unix는 `exec`로 프로세스 교체, Windows는 자식 프로세스로 실행하고 종료 코드 반환. 암호와 패스프레이즈 입력, 호스트 키 확인은 ssh가 처리
- 입력 검증 표: 닉네임, 유저, 주소, 포트(1-65535), 키 파일 규칙(`src/validate.rs` 기준)
- 환경변수 표: `SSHTUI_SSH_DIR`

### 4. ssh config 연동

- 읽기: `Include` 확장(상대 경로는 ssh 디렉터리 기준, glob, `~`), 와일드카드(`*`, `?`, `!`)와 `Match` 블록 제외, 항목별 출처 파일과 줄 번호, 적용값은 `ssh -G <닉네임>` 결과
- 새 호스트 저장: 파일이 없으면 생성(Unix 권한 600, 디렉터리 700), 삽입 위치(첫 번째 와일드카드 `Host` 블록 또는 `Match` 블록 앞, 그 블록에 붙은 주석이 있으면 주석 앞, 없으면 파일 끝)와 이유(ssh는 옵션마다 먼저 나온 값을 사용), 블록에 쓰는 옵션(`HostName`, `User`, `Port`, `IdentityFile` 중 입력된 것만), 따옴표 처리, 저장 후 `ssh -G` 결과와 다르면 경고
- 편집과 삭제: 정의된 파일에서 직접 수정(Include 대상 포함), 최소 변경(바뀐 줄만 수정, 추가, 삭제. 나머지는 바이트 단위 보존), 폼에는 블록에 직접 적힌 값만 채우고 상속 값은 `inherited:` placeholder, 비운 필드는 줄 삭제, 폼으로 표현할 수 없는 구성(예: `IdentityFile` 여러 줄)은 읽기 전용, 여러 패턴 블록의 처리(옵션 변경은 공유, 이름 변경과 삭제는 해당 패턴만, 마지막 패턴 삭제 시 블록 전체 삭제), 저장과 삭제 전 diff 확인, 쓰기 권한 없는 파일은 읽기 전용
- 쓰기 공통 규칙: 쓰기 직전 다시 읽어 외부 변경 시 중단하고 다시 불러오기, 백업(같은 디렉터리의 `.<파일명>.sshtui.bak`, 1개를 덮어씀, 이름이 `.`으로 시작하는 이유는 `Include conf.d/*` 같은 glob에 걸리지 않게 하기 위함), 임시 파일에 쓴 뒤 교체, 심볼릭 링크는 링크를 유지하고 대상 파일 수정, 기존 권한 유지
- 닉네임 규칙
- 알려진 제한 표:
  - `Include` 인자의 `${VAR}`와 `%` 토큰은 확장하지 않고 경고 표시
  - `~user` 형태는 확장하지 않음
  - 블록 삭제 시 블록 위의 주석 줄은 남김
  - 교체 방식 저장이므로 하드 링크는 끊어짐
  - `SSHTUI_SSH_DIR` 사용 시 ssh에 `-F <dir>/config`를 전달. 이때 ssh는 상대 경로 `Include`를 실제 `~/.ssh` 기준으로 풀므로 목록과 적용값이 다를 수 있음
  - 상세 패널의 `Key file`은 `ssh -G`가 출력하는 값이므로, 설정이 없으면 ssh 기본 키 경로들이 표시됨

### 5. 네이티브 파일 다이얼로그

- OS별 표: 수단, 숨김파일 표시 여부, 비고
  - macOS: `osascript`의 `choose file ... with invisibles`, 강제 표시
  - Windows: `rfd` crate(`IFileOpenDialog`, `FOS_FORCESHOWHIDDEN`), 강제 표시
  - Linux과 그 외 Unix: `zenity --file-selection`(KDE 데스크톱에서 `kdialog`가 있으면 `kdialog --getopenfilename`), 강제 불가이며 화면에 안내 문구 표시(zenity는 `Ctrl+H`, kdialog는 `Alt+.`)
- 공통 동작: 시작 위치는 ssh 디렉터리, 취소 시 폼으로 복귀하고 기존 입력값 유지, 종료 후 화면 전체 다시 그리기
- 비활성 조건과 표시 문구(소스의 문구 그대로): SSH 접속 중, Linux에서 `DISPLAY`와 `WAYLAND_DISPLAY` 없음, zenity와 kdialog 모두 없음
- Linux에서 `rfd`와 XDG portal을 쓰지 않는 이유: portal의 FileChooser에 숨김파일 옵션이 없고 `rfd`의 숨김파일 옵션은 GTK3 백엔드 전용

### 7. 수동 확인 절차

실제 `~/.ssh`를 건드리지 않고 확인하는 절차를 번호 목록으로 쓴다. 각 단계는 실행할 명령 또는 누를 키와 기대 결과를 포함한다.

1. 임시 디렉터리 준비: 임시 ssh 디렉터리에 `Host web`(HostName 127.0.0.1, User, Port), 여러 패턴 블록, `Host *` 블록이 든 config와 가짜 키 파일(첫 줄만 `-----BEGIN OPENSSH PRIVATE KEY-----`)을 만드는 명령. 이 config에 상대 경로 `Include`를 넣지 않는 이유 한 줄
2. 실행: `SSHTUI_SSH_DIR=<임시 디렉터리> sshtui`
3. 목록과 상세 패널 확인
4. 새 접속 저장(`n`, 닉네임 입력) 후 config에 블록이 `Host *` 앞에 들어갔는지, 백업 파일이 생겼는지 확인
5. 편집(`e`)에서 값 변경과 diff 확인, 저장 후 다른 줄이 그대로인지 `diff`로 확인
6. 삭제(`d`)와 diff 확인
7. 외부 변경 감지: 확인 화면에서 다른 터미널로 config를 수정한 뒤 `y`
8. 키 목록(`Ctrl+L`)과 찾아보기(`Ctrl+O`): 다이얼로그가 ssh 디렉터리에서 열리고 숨김파일이 보이는지, 취소 시 입력값 유지, 종료 후 화면이 온전한지
9. SSH 접속 중 실행 시 찾아보기 비활성 문구
10. 실제 접속: 접속 가능한 서버로 1회 접속과 저장 후 접속, 종료 후 터미널 상태(에코, 커서) 정상 여부
11. 터미널에서 `ssh -F <임시 config> <닉네임>`으로 저장한 호스트를 그대로 쓸 수 있는지
